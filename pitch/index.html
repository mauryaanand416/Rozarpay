The problem

Fraud eats margin three ways

Missed fraud

Card testing, account takeover and new-card abuse drain balances before anyone notices. Every missed rupee is gone.

False positives

Blocking a legitimate ₹50,000 order destroys trust and revenue. Naive models over-block.

Unexplainable reviews

Analysts get a score with no reasons. Reviews take longer, decisions can't be defended to customers or regulators.

AI-enabled fraud is accelerating across Indian BFSI while returns and chargebacks quietly eat margin.

What we built

One engine, the full risk loop

  • Real-time scoring — 21 behavioral features, LightGBM detector, ~30–45 ms end-to-end
  • Velocity rules layer — card-testing bursts, account-drain, device farms; rules escalate, never de-escalate
  • Gated actions — ALLOW → REVIEW → BLOCK, and above ₹40k the system must escalate to a human
  • Explainable by default — SHAP attributions on every decision + LLM narrative with template fallback
  • Tamper-evident audit ledger — SHA-256 hash chain; analyst actions are inside the perimeter too
  • Feedback loop — review verdicts become labels; one click retrains and hot-swaps the model

Under the hood

Detection: boring tech, honest math

Features that matter

Velocity windows (1h / 24h / 30-day), spend-vs-normal ratio, IP↔billing country mismatch, night-time flag, CVV/AVS results, card age, device activity, prior confirmed fraud on the account.

Why LightGBM?

Gradient-boosted trees remain state-of-the-art for tabular payments data. Trains in minutes, scores in microseconds, and gives exact SHAP values — defensible engineering, not fashion.

Rules beside the model

CARD_TESTING_BURST, NEW_CARD_HIGH_VALUE, GEO_MISMATCH_HIGH_VALUE, ACCOUNT_DRAIN_PATTERN… deterministic guarantees regulators expect.

Time-based split

Train on the past, test on the future. Random splits leak the future into training and inflate metrics. Ours mirrors production reality.

Operating points are learned from data

  • t_review maximizes F2 subject to recall ≥ 80% — missing fraud costs more than extra review
  • t_block demands maximum precision subject to recall ≥ 50% — auto-blocking must be near-certain
  • A rupee cost model sweeps thresholds to minimize missed-fraud value + ₹150 friction × false positives

Explainability

Every decision carries its reasons

 SIM-B1594DC95E · ₹67,027 · netbanking · REVIEW   score 0.02
   rule  GEO_MISMATCH_HIGH_VALUE  foreign IP, high-value order
   rule  NIGHT_LARGE_AMOUNT       large amount between 00:00–05:00
   model top drivers: country_mismatch (+0.31), hour_sin (+0.22)
   llm   “Held for manual review: foreign-IP high-value order at night
          matches account-takeover patterns seen this month.”

SHAP is stored synchronously — always available. The LLM narrative is async: if Azure OpenAI is down or no key is set, a deterministic template takes over. Zero dependency, zero silence.

Bounded autonomy

The agent cannot move money. Ever.

  • Actions are recommendations: allow, hold for review, block, escalate — nothing else
  • Hard gate: above ₹40,000 auto-block is suppressed — a human decides
  • Analyst resolutions are audited under their identity and feed retraining
  • Rate limiting, webhook alerts, safe-mode if the model fails to load

 GET /audit/verify → {"valid": true, "entries": 42}
 edit any row  →  {"valid": false, "broken_at_seq": 42}

Each entry hashes its content plus the previous hash (SHA-256). Silent history edits are detectable — a risk product whose own log could be edited would be indefensible.

Failure handling — demonstrated live

Four ways it refuses to fail badly

Model won't load

Safe mode: everything routes to human review. Never fails open.

LLM provider down

Circuit breaker opens after 3 failures; template explanations take over instantly.

High-value false positive

Human gate — escalated instead of silently blocked. A person releases it.

Ledger tampering

Chain verification pinpoints the first broken sequence number.
